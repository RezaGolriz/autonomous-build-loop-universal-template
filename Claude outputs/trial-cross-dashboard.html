# WI-001: Add slugify() to textkit

Kind: feature

## Outcome

`textkit.slugify(text)` turns any string into a URL-friendly slug: lowercase,
words separated by single hyphens, only `a-z`, `0-9` and `-` remain, no leading
or trailing hyphen. Example: `slugify("Hello, World!  Again")` returns
`hello-world-again`. Unit tests in `tests/test_textkit.py` cover it. The
existing `word_count` keeps working.

## Acceptance criteria

- `textkit.slugify` is publicly importable and accepts every Python `str`
  value without raising an exception.
- `slugify("Hello, World!  Again")` returns exactly
  `"hello-world-again"`.
- ASCII letters are lowercased, ASCII digits are preserved, and every maximal
  run of characters outside `a-z`, `A-Z`, and `0-9` becomes one hyphen between
  adjacent retained runs.
- The result contains only `a-z`, `0-9`, and `-`; it never starts or ends with
  a hyphen and never contains consecutive hyphens.
- The empty string, and any string containing no ASCII letter or digit, returns
  the empty string.
- Unit tests in `tests/test_textkit.py` independently cover the documented
  example, case conversion, digits, repeated and edge separators, empty input,
  input with no retained characters, and continued correct behavior of
  `word_count`.
- The project test command succeeds using only the standard library:
  `python3 -B -m unittest discover -s tests -q`.

## Out of scope

- Transliteration, locale-aware normalization, or preservation of non-ASCII
  letters; non-ASCII characters are separators under this work item.
- Percent-encoding, URL parsing, domain/path construction, or validation of a
  complete URL.
- Configurable separators, case rules, or character allowlists.
- Accepting, coercing, or defining error behavior for non-`str` inputs.
- A command-line interface or changes to APIs other than adding `slugify` and
  preserving the existing `word_count` behavior.

## Constraints and invariants

- Standard library only; no new dependencies.
- Only `src/**` and `tests/**` may change during EXECUTE.

## Design

Add `slugify(text: str) -> str` directly to `src/textkit/__init__.py`, alongside
the existing public `word_count` function. Use the standard-library `re` module
with an explicit ASCII allowlist: replace each maximal run matching
`[^A-Za-z0-9]+` with `-`, strip leading and trailing hyphens, then lowercase the
retained ASCII letters. Because the replacement operates on arbitrary Python
`str` values and treats every non-ASCII character as a separator, it requires
no transliteration, normalization, coercion, or dependency. Defining the
function at module scope makes it available as `textkit.slugify` without
changing the existing API.

Extend `tests/test_textkit.py` with separate unit-test cases for the documented
example, ASCII case conversion, digit preservation, repeated and edge
separators, empty input, input with no ASCII alphanumeric characters, and
non-ASCII characters acting as separators. Retain the existing `word_count`
test as regression coverage. The full standard-library unittest discovery
command is the deterministic proof for both the new behavior and preservation
of the existing behavior.
